# 空设备连接已有加密备份

用户在独立 Edge 测试窗口、本地零书签时无法启用 E2E，错误要求先确认发布清空。原因是启用 E2E 一律调用上传迁移，触发空树推送保护。

修复位于共用 migrateEncryption 入口：无候选文件、本机未启用、请求启用且最新云端文件为 .enc 时，使用输入密码下载、解密、解压并校验完整备份，再复核最新路径和修改时间；成功只保存本机 E2E 设置，不上传、不删除、不创建同步基线。用户随后在同步面板选择拉取。该分支与本地书签数量无关，保护有本地书签的新设备同样不被意外上传。

原有候选迁移、已启用后的改密/关闭、明文云端迁移仍走原流程；不绕过清空保护。错误密码、损坏内容或版本变化均不保存新设置。既有恢复锁、迁移目标检查与同步锁保留。

- 616 项全量单元测试通过；随后增强空设备成功用例，调用 smartPull 证明已保存密码可用于拉取解密（书签写入仓储与快照使用 mock），最终迁移测试 26 项通过。
- Chrome/Firefox 构建和类型检查通过；git diff --check 通过。既有包体积/Browserslist 警告保留。
- 未使用用户真实云端账号验收。路径/mtime 复核不构成服务端事务；之后拉取仍会校验实际最新备份。

## 本地复测

在原测试 Edge 的扩展管理页对 MarkSync 点击“重新加载”，重新打开面板。输入云端原密码开启 E2E，看到已验证提示后回同步面板选择拉取。不要为加入已有加密库而确认发布清空。
