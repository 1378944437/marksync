# 抽屉纵向稳定性修复（2026-09-20）

## 根因

1.6.4 仅稳定滚动条占位，未固定抽屉高度。共用 Drawer 使用内容自适应高度（max-height:90%）和弹簧 y 轴入场动画；异步加载、空态切换、展开操作会改变底部定位面板的顶部位置。此前只检查宽度，没有覆盖纵向位置，是验收遗漏。

基于已发布 1.6.4 本地构建复现：390×740 手机页中，短内容增加合成长列表后顶部由 513px 变为 74px；1280×900 控制台由 693px 变为 90px。逐帧记录同时检测到原先的滑入移动。见 baseline.json。

## 修复

共用 Drawer 固定高度为可用视口的 90%，仅使用 opacity 淡入；取消自动 y 轴动画，并禁用内部列表的自动滚动锚定。标题区固定，只有内容区滚动。空列表也保留相同外框空间，避免数据到达后突然扩张。仍保留用户主动拖动把手关闭的交互，以及既有横向滚动条占位。

## 验证

- 增强 scripts/verify-drawer-width.cjs：新增打开过程逐帧 top、内容增减前后 top 的断言。六种桌面/手机视口与模式、三个入口共 18 个场景通过，横纵位移均为 0px；另两个控制台滚动条检查通过。见 results.json。
- 增强 scripts/verify-responsive-panels.cjs：新增真实列表展开及恢复确认取消返回后的 top/height 断言。桌面、320–430px 手机竖屏、横屏、平板、20px 根字号，中英文/明暗主题共 48 个场景通过。见 interactions/results.json。
- pnpm build：Chrome/Firefox 类型检查和构建通过；既有 Browserslist 过期与包体积警告保留。
- git diff --check 通过。纯 UI 改动，未重复全量同步业务单元测试。

测试使用隔离 Edge 配置，长内容与列表数据均为合成数据。手机为视口/触屏/UA 模拟，不代表所有实际手机浏览器通过；旋转或系统键盘导致的真实视口尺寸变化仍会让面板按视口正常调整。未执行实体手机或原生 Firefox UI 验收。
