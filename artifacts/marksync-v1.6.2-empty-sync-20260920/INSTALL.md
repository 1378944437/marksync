# MarkSync 空树同步候选包 · 2026-09-20

显示版本仍为 **1.6.2**；本批由文件名中的 `empty-sync-20260920` 和 `SHA256SUMS.txt` 区分。请在参与验收的设备上使用同一批包，不能只核对版本号。

## Chrome / Edge

1. 将 `marksync-chrome-v1.6.2-empty-sync-20260920.zip` 解压到固定目录，根目录应直接包含 `manifest.json`。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择该目录。ZIP 用于解压加载。
4. 已通过解压方式安装的设备可更新原加载目录后点“重新加载”；保留原目录副本作为回退依据，不要为了更新先卸载扩展，卸载可能丢失扩展设置与本地快照。

## Firefox 临时测试

1. 使用 Firefox 140 或更新版本（来自包内 manifest 的最低版本要求）。
2. 打开 `about:debugging#/runtime/this-firefox`，点击“临时载入附加组件”。
3. 选择 `marksync-firefox-v1.6.2-empty-sync-20260920-unsigned.xpi`；也可解压后选择根目录中的 `manifest.json`。

此包未签名，只用于临时加载，重启后临时安装失效；不是正式 Firefox 永久安装包。

## 两设备验收

使用独立浏览器测试配置、专用测试 WebDAV 目录或测试 Gist。首次启用清空前，确保双方已安装本批构建；测试目标不与原有同步设备共用。

1. 两设备都只选择“书签栏”。A 新建一条测试书签，上传后由 B 拉取。B 另在“其他书签”放一条范围外书签。
2. A 删除书签栏最后一条，触发同步。应出现“确认发布清空”；未确认时 B 的书签仍在，云端已有备份保留。
3. A 核对目标、范围及数量，发布清空。B 定时或手动同步时应要求确认；确认前不删除，也不自动合并并重新上传旧书签。
4. B 确认后书签栏为空，“其他书签”仍在。B 从本地快照恢复清空前内容，确认能找回测试书签；不要接着向原有生产目标上传。
5. 再产生一次接收提示，先新增一条本地书签再点旧确认按钮。此次应停止并要求重新确认，新增书签保持原样。
